# AutoDL 自动抢机助手（Tampermonkey 脚本）

在已登录的 AutoDL“租用新实例”页面（或算力市场、实例列表页面）里监测空闲 GPU，发现符合条件的主机后自动“创建并开机”一台按量计费实例，并在创建请求里带上你设置的数据盘扩容。

成品文件：`dist/autodl-grabber.user.js`（单文件，无外部依赖）。

> **先读这一段。** 点击“开始自动抢机”后没有确认步骤：一旦出现符合条件的主机，脚本会直接创建并开机，随即开始计费。
> 创建请求本身从未被实际发送过：它的格式来自对 AutoDL 前端代码的阅读，创建之后的流程只在自动化测试里跑过。
> 第一次使用请守在页面前，详见[验证状态](#验证状态)。

## 安装

1. 浏览器安装 [Tampermonkey](https://www.tampermonkey.net/)。新版 Chrome 还需要在扩展管理页为 Tampermonkey 打开“允许用户脚本”（或开发者模式），否则脚本不会运行。
2. 打开 Tampermonkey 管理面板 → “实用工具” → “导入文件”，选择 `dist/autodl-grabber.user.js`；或新建脚本后把文件内容整体粘贴进去保存。已装过旧版时，导入会提示覆盖。
3. 登录 AutoDL，打开下面任一页面，右下角出现“AutoDL 自动抢机助手”面板即安装成功。

脚本生效的页面：

| 页面 | 网址 | 面板初始状态 |
| --- | --- | --- |
| 租用新实例（创建实例） | `https://www.autodl.com/create` 及 `/create/…` | 展开 |
| 算力市场 | `https://www.autodl.com/market/…` | 展开 |
| 容器实例列表 | `https://www.autodl.com/console/instance/list` | 收起（点标题栏展开） |

平时的入口是“控制台 → 容器实例 → 租用新实例”：在实例列表页面板就已经加载，点“租用新实例”后它会跟着留在创建页上。AutoDL 是单页应用，如果你是从其他页面（例如控制台首页）一路点过来而面板没有出现，刷新一次即可。

面板固定在右下角，位于创建页底部“取消 / 创建并开机”那一栏的上方，不会挡住页面自己的按钮。脚本不读取也不操作创建页上的表单：你在页面上选的主机、镜像与面板里的配置互不影响。

## 配置说明

| 项目 | 说明 |
| --- | --- |
| GPU 型号 | 可多选，任一型号有货即可。列表来自平台。 |
| GPU 数量 | 一台实例的卡数（1～12）。主机有“N 卡起租 / 按 N 卡倍数租用”规则时按创建页的规则判断。 |
| 地区 | 与算力市场页的地区一致。勾选的顺序就是优先级，可用“上移 / 下移”调整；优先级高的地区先被检查和尝试，同一地区内选更便宜的主机。 |
| 每小时价格上限 | 整台实例（全部 GPU）每小时的实付价，已含你的会员折扣，不含数据盘费用。创建前以平台“价格预览”返回的价格为准再核对一次。 |
| 镜像 | “官方镜像”是 AutoDL 的基础镜像（框架 / 版本 / Python / CUDA）；“我的自定义镜像”是你在“我的镜像”里保存的镜像。不支持社区镜像和克隆码。 |
| 数据盘扩容 | 见下一节。 |
| 监测间隔 | 10～3600 秒，默认 30 秒。 |

配置保存在浏览器本地（`localStorage`），刷新后保留；任务不会随刷新自动恢复。

### 数据盘扩容的含义

**填写的是“额外增加多少 GB”，不是扩容后的总容量。** 总容量 = 主机自带的免费数据盘（目前看到的都是 50 GB）+ 你填写的大小。

这是在 AutoDL 创建实例页面上核实的（2026-11-13，前端版本 v6.55.0）：

- 页面显示“数据盘：免费 50GB ☐ 需要扩容”，勾选后出现输入框，占位文字是“容量范围:0~405”，与该主机在列表里的“可扩容：405GB”一致。
- 实例规格一栏显示为“免费 50GB SSD，付费 N GB”。
- 前端把输入值乘以 1024³ 作为 `expand_data_disk`（字节）提交。
- 账号里一台已有实例的数据：付费扩容 200 GB，数据盘总容量 250 GB。

规则（与创建页的输入框一致）：整数 GB，最小 0（0 表示不扩容），步长 1，上限是所选主机当前的“可扩容”空间。上限因主机而异，所以不在面板里写死，而是逐台主机判断：**空间不够的主机直接跳过，不会改用更小的容量。**

需要注意：平台的价格预览接口不校验上限（实测对一个远超上限的值也返回了成功），所以上限由脚本根据主机数据自己把关。

### 扩容费用

扩容的价格因主机而异，只有找到具体主机后才能向平台询价。脚本在创建前核对时取得平台的预览价，写入运行日志（例如“数据盘扩容 100 GB（￥0.67/日）”），并显示在任务结果里；取不到预览价时不会创建。结果里拿不到费用时显示“未知”，脚本不会自己估算。

实测参考：100 GB 为 ￥0.67/日，即原价 ￥0.007/GB/日打会员 95 折。

按量计费实例的付费数据盘**按日扣费，关机期间也扣**（创建页原文：“将按 … 元/日/GB 在每日 24 点进行扣款（无论实例是否关机）”）。

## 一次任务的流程

1. 点“开始自动抢机”。配置校验通过后任务立即开始，没有确认框；这次点击就是对本次任务的授权，本次配置会完整写进运行日志的第一行。
2. 每个监测周期先读各地区“按型号的空闲数量”（算力市场页型号旁边的那组数字，请求很小）；只有平台显示某地区有足够空闲卡时，才去读那个地区的主机列表。
3. 对候选主机做创建前核对：重新读取该主机、主机是否在维护、实例数量是否到上限、平台价格预览（价格和扩容大小）、镜像是否还在、实例列表里有没有任务开始后新冒出来的实例。任何一项不符就不创建。
4. 提交创建请求（数据盘扩容随请求一并提交，AutoDL 支持创建时扩容，不需要创建后再分步扩容）。
5. 在实例列表里确认实例出现、扩容大小与设置一致、状态变为运行中，然后停止监测并通知。

一次任务最多创建一台实例。

### 不会重复创建的保证

- 同一时间只有一个标签页能运行任务（浏览器的 Web Locks；不支持的浏览器拒绝启动）。
- 连点“开始自动抢机”只会启动一个任务。
- 一个任务内创建请求串行，不会并发。
- 创建请求超时、断网或返回看不懂时，**不重发**，而是用约 2 分钟反复查实例列表：出现了新实例就按成功处理；确认没有才允许再试，且一个任务最多容忍 2 次这种情况。
- 创建请求发出时会在本地记一个“未确认”标记。如果此时页面被刷新或关闭，下次启动会先核对实例列表，发现多出实例就拒绝启动并提示你去控制台确认。
- 任务开始后，如果实例列表里出现了不是本任务创建的新实例（例如你在别处手动创建），任务立即停止。

### 什么时候暂停、什么时候停止

- **暂停并通知，等你处理后点“继续”：** 登录失效、平台要求验证码/人机验证（不会绕过）、权限不足、余额不足、需要实名、未支付订单过多、创建前价格超过上限、实例数量到上限、接口返回与预期不符。
- **有限重试：** 网络错误、超时、服务器 5xx、被限流。等待时间按 2 倍递增（上限 5 分钟），连续 6 次失败后暂停。
- **停止并提示可能在计费：** 实例已创建但扩容大小与设置不符；实例已创建但开机失败；平台说创建成功但实例迟迟不出现；无法完成核对。这些情况下不会再创建别的实例。

“停止”按钮立即取消后续监测和重试。如果创建请求已经发出，脚本会明确提示无法保证撤销，并继续把结果核对完，但不会再发起新的创建。

## 验证状态

验证环境：2026-11-13，AutoDL 前端 v6.55.0，Chrome 157，一个带实例权限的**子账号**。开发期间没有创建任何实例，也没有做任何付费扩容。

**在真实页面上实际验证过（全部是只读请求）**

- 沿用页面登录状态请求接口（含子账号的 `/api/v1/sub_user/` 路径）。
- 地区、GPU 型号、官方镜像、会员等级的读取与面板展示。
- 按型号空闲数量、主机列表、主机在线检查、实例数量、价格预览、实例列表这些接口的请求与返回字段。
- 监测 → 发现候选主机 → 全部创建前核对通过（实际找到过符合条件的主机，核对后在提交创建前停下；这一步是用开发阶段带“提交前停止”开关的构建验证的，当前版本去掉了这个开关，核对代码没有变）。
- 当前版本：点“开始自动抢机”后不弹确认、直接进入监测，连点只启动一个任务，“停止”后不再发请求（用一组不可能匹配的条件测试）。
- 扩容报价（100 GB → ￥0.67/日）与创建页显示一致；扩容的含义、范围在创建页上核实。
- 两个标签页的任务锁（第二个标签页被拒绝，第一个停止后第二个可以启动）、刷新后配置保留且任务不恢复。
- 面板在“租用新实例”页面上的加载与位置：展开和收起时都不遮挡页面的“创建并开机”按钮；从实例列表点“租用新实例”后面板保留。
- 上述测试期间页面上装了一个只放行只读接口的拦截器，脚本没有触发过任何被拦截的请求。

**只在自动化测试里验证过（96 个测试，使用测试目录里的模拟平台）**

- 创建请求发出之后的全部流程：实例出现、扩容核对、等待开机、成功通知。
- 创建超时后的核对（实例已建 / 未建两种）、被抢先（卡数不足）、余额不足、登录失效、限流退避、价格上涨、可扩容空间变小、扩容未生效。
- 启动互斥、暂停/继续、创建过程中点停止。

**没有验证过**

- **创建请求本身。** 请求体照着前端创建页的代码构造，没有发送过；成功时返回值的格式是从前端代码推断的。即使格式有出入，脚本会把它当作“结果不明确”去查实例列表，而不是重发。
- 创建后实例的状态名：只见过 `running`，失败状态名来自前端代码。
- 自定义镜像：测试账号没有自定义镜像，列表的解析只有代码依据。
- 主账号（非子账号）下的运行。
- 验证码：创建流程里没有遇到过，脚本只能靠返回信息里的关键词识别，识别到就暂停。
- 通过 Tampermonkey 安装运行当前版本：测试时是把构建产物直接注入页面执行的。
- 平台的限流阈值：没有找到公开说明，也没有去试探。

## 已知限制

- **空闲数量不是完全准确的信号。** 实测 20 个型号里有 1 个出现过“统计为 0 但实际有 1 张可租”的情况，所以偶尔会晚一个周期甚至漏掉；反过来统计有货但主机都不合适时，同一地区的主机列表最多每 60 秒重读一次。平台的主机列表不保证把有货的主机排在前面（排序参数实测无效），所以没有采用“只看第一页”的做法。
- **标签页必须保持在前台可见。** 实测 Chrome 会把隐藏窗口里的定时器暂停数分钟。建议把这个页面单独放一个窗口。任务运行中页面转入后台时日志里会有提醒。
- 只支持按量计费、NVIDIA GPU、不使用优惠券；不提供潮汐算力区、企业专区。
- 一个地区匹配的主机超过 1000 台时只检查前 1000 台（日志会提示）。
- 价格上限只管实例价格，不含数据盘费用。

## 隐私与权限

- `@grant none`、没有 `@require` / `@connect`：不申请任何特权接口，不加载远程脚本。
- 所有请求都发往当前页面同源的 `/api/v1/...`，产物里没有任何其他网址，没有统计或遥测。
- 登录令牌在每次请求时从页面的 `localStorage` 读取，不复制、不保存、不写日志；日志在写入前会过滤令牌和常见敏感字段。
- 脚本自己保存的只有：配置（`autodl-grabber:draft`）和“未确认的创建请求”标记（`autodl-grabber:pending-create`，内容是时间、主机 ID、当时已有的实例 ID）。
- 实例列表里的 SSH 密码、Jupyter 令牌等字段不会被读取。

## AutoDL 改版后改哪里

症状通常是任务暂停并提示“接口返回与脚本预期不符”，提示里会带上出问题的接口和字段。

| 变化 | 修改位置 |
| --- | --- |
| 接口路径 | `src/autodl/api.ts` 的 `ENDPOINTS` |
| 请求参数（筛选条件、创建请求体） | `src/autodl/api.ts` 的 `machineQuery` 和 `createInstance` |
| 返回字段名、字段含义 | `src/autodl/wire.ts`（每个接口一个 schema 和一个转换函数） |
| 错误码（余额不足、卡数不足等） | `src/autodl/http.ts` 的 `KIND_BY_CODE`、`KIND_BY_KEYWORD` |
| 登录令牌的存放位置、请求头 | `src/autodl/http.ts` 的 `STORAGE_KEYS` 和 `createHttp` |
| 镜像与主机的兼容规则 | `src/domain/select.ts` 的 `imageMismatch`、`MIN_CUDA_BY_SERIES` |
| 实例失败状态名 | `src/runner/runner.ts` 的 `FAILED_STATUSES` |
| 脚本生效的网址 | `build.mjs` 里的 `@match` / `@exclude` |
| 面板位置（避让页面底部栏） | `src/ui/styles.ts` 的 `.panel` |

核对方法：在 AutoDL 页面打开开发者工具的“网络”面板，手动操作一遍，对照上表的请求和返回。改完后执行 `pnpm test && pnpm build`。

脚本没有依赖页面的 DOM 结构或 CSS 选择器，所以页面样式调整不影响它。

## 开发

```bash
pnpm install
pnpm test        # 96 个测试
pnpm typecheck
pnpm lint
pnpm build       # 生成 dist/autodl-grabber.user.js
```

目录：`src/domain`（筛选与配置规则）、`src/autodl`（接口适配）、`src/runner`（任务状态机）、`src/app` 与 `src/ui`（面板）；`test/simulator.ts` 是测试用的模拟平台，不会打进成品。
